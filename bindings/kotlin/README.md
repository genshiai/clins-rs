# clins-kt

Kotlin/JVM **21+** over the native Rust Core, generated by UniFFI with JNA.
Kotlin source uses `.kt`; `clins-kt` is the SDK name. Android and Kotlin Multiplatform are
not claimed by this initial JVM binding.

Prepare `data/definitions.json` using the root README, then:

```sh
cd bindings/kotlin
./gradlew test jar nativeJar publishAllPublicationsToLocalBuildRepository
```

The Gradle task builds the Rust cdylib and generator, then generates the Kotlin API.
`build/libs` contains the JVM jar, sources jar and a native jar classified by the host
(`darwin-aarch64`, `linux-x86-64`, etc.). `build/repository` is a local Maven repository.
A remote Maven Central upload requires publisher credentials and is not implied by this task.

A Maven consumer needs the API and the matching runtime classifier:

```kotlin
dependencies {
    implementation("jp.genshi:clins-kt:0.1.0-alpha.1")
    runtimeOnly("jp.genshi:clins-kt:0.1.0-alpha.1:darwin-aarch64")
}
```

```kotlin
import jp.genshi.clins.Validator
Validator(definitionsJson).use { validator ->
    val report = validator.validateJson(resourceJson, null)
}
```

Malformed JSON raises `ClinsException.InvalidInput`; observed validation violations return
an invalid report. Keep resource JSON as text to preserve numeric precision. Native artifacts
must match OS/CPU. Building a classifier does not verify other operating systems.
